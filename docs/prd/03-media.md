# Media PRD

버전: v0.1 | 작성자(PM): | 최종 수정일: 2026-10-23 | 현재 완성도: 70

## 1. 가치 정의

김서연은 글에 넣을 사진을 Admin에 업로드하고, 독자는 그 사진을 빠르게 로드되는 크기로 김서연의 도메인에서 본다. 그 결과 김서연은 외부 이미지 호스팅에 기대지 않고 자기 글의 이미지를 직접 관리한다.

## 2. 배경

글에 사진을 넣을 때 원본 그대로 올리면 방문자가 큰 파일을 내려받아 느리고, 외부 호스팅을 쓰면 글이 그 서비스에 묶인다. Cloudcore는 업로드할 때 Cloudflare Images binding으로 webp 두 크기를 만들어 R2에 두고, Media 전용 커스텀 도메인으로 서빙한다(ADR-0003). 전달 시점 변환은 쓰지 않아 무료 변환 한도를 업로드에만 쓴다.

## 3. 맥락

업로드는 에디터의 이미지 Card, 글의 대표 이미지·OG 이미지, Site Settings의 로고·아이콘에서 일어난다. Media는 누구나 업로드할 수 있고, 삭제는 업로더와 Owner가 한다(map). 파일은 R2 버킷에 저장되고 `media.<도메인>`에서 공개된다.

## 4. 페르소나

김서연은 글마다 사진 1~3장을 올리고, 가끔 대표 이미지를 바꾼다. 이도현은 자기 글에 스크린샷을 올린다.

## 5. 메인 시나리오

김서연은 에디터에서 이미지 Card를 열고 사진 두 장을 끌어다 놓는다. 업로드가 끝나자 각 이미지 아래에 대체 텍스트 입력란이 보이고, 그녀는 사진 설명을 적는다. 본문에는 데스크톱 크기 이미지가 보인다.

그녀는 Media 목록을 열어 방금 올린 사진을 확인한다. 목록에는 파일 이름, 크기, 올린 사람, 올린 시각이 보인다. 나중에 같은 사진을 다른 글에 다시 쓰고 싶어 Media 목록에서 파일을 골라 본문에 넣는다.

이도현도 자기 글에 스크린샷을 올린다. 그는 자신이 올린 Media를 삭제할 수 있지만, 김서연이 올린 Media는 삭제 버튼이 보이지 않는다.

## 6. 사용자 여정 (one-way)

파일 선택 또는 끌어다 놓기 → 업로드 → 변환 → 본문에 삽입 → 대체 텍스트 입력 → (필요하면) Media 목록에서 재사용 → (필요하면) 삭제

## 7. 유즈 케이스

### UC-M01 이미지를 업로드할 수 있다
- 시작 조건: 김서연이 에디터나 Media 화면에서 파일을 골랐다.
- 사용자 행위: 김서연은 이미지 파일을 업로드하고 진행 상태를 볼 수 있다.
- 결과/정책: 업로드가 끝나면 Media 항목이 만들어지고 본문이나 대표 이미지에 바로 쓸 수 있다. 업로드한 사람과 시각이 기록된다.
- 관련 시나리오 구간: 사진 두 장 업로드.

### UC-M02 업로드한 이미지가 두 크기로 변환된다
- 시작 조건: 이미지 업로드가 끝났다.
- 사용자 행위: 김서연은 특별한 조작 없이 데스크톱·모바일 크기의 webp 이미지를 얻게 된다.
- 결과/정책: 원본은 보관하지 않고 webp 두 벌만 R2에 둔다. 변환에 실패하면 업로드는 실패하고 다시 시도할 수 있다.
- 관련 시나리오 구간: 업로드 → 변환.

### UC-M03 대체 텍스트와 캡션을 적을 수 있다
- 시작 조건: 이미지가 본문에 들어갔다.
- 사용자 행위: 김서연은 이미지의 대체 텍스트와 캡션을 적을 수 있다.
- 결과/정책: 대체 텍스트가 비면 Site는 `alt`를 비워 두고, 업로드 시 파일 이름을 기본값으로 제안한다. `[가정]`
- 관련 시나리오 구간: 대체 텍스트 입력.

### UC-M04 Media 목록에서 다시 쓸 수 있다
- 시작 조건: 김서연이 Media 목록을 열었다.
- 사용자 행위: 김서연은 파일 이름과 썸네일로 Media를 찾아 본문에 넣을 수 있다.
- 결과/정책: 목록은 최근 업로드 순이고, 파일 이름으로 검색할 수 있다. `[가정]`
- 관련 시나리오 구간: Media 목록에서 재사용.

### UC-M05 삭제 권한이 있다
- 시작 조건: 이도현이 Media 목록을 열었다.
- 사용자 행위: 이도현은 자신이 올린 Media만 삭제할 수 있고, 김서연은 모든 Media를 삭제할 수 있다.
- 결과/정책: 삭제하면 R2 객체와 Media 항목이 사라지고, 그 Media를 쓰는 글은 깨진 이미지를 보여 준다. `[확인 필요]` 참조 중인 Media 삭제를 막을지 경고만 할지.
- 관련 시나리오 구간: 삭제.

### UC-M06 이미지 URL이 공개 도메인에서 서빙된다
- 시작 조건: Media가 본문이나 대표 이미지에 쓰였다.
- 사용자 행위: 독자는 Site에서 이미지를 본다.
- 결과/정책: 이미지는 `media.<도메인>`의 긴 캐시 헤더와 함께 제공되고, Site Build에 의존하지 않는다.
- 관련 시나리오 구간: 독자가 글을 읽는다.

## 10. 열린 질문과 결정 기록

- `[확인 필요]` 삭제한 Media를 참조하는 글의 처리(차단/경고/깨진 이미지 허용).
- `[확인 필요]` 파일 크기 상한과 허용 형식 목록.
- `[확인 필요]` Media 목록 검색과 페이지네이션 방식.
- 결정: 업로드 시 두 크기 webp 변환, 원본 미보관(ADR-0003).
- 결정: Media는 누구나 업로드, 삭제는 업로더와 Owner(map).
