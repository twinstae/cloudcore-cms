# 멤버와 인증 PRD

버전: v0.1 | 작성자(PM): | 최종 수정일: 2026-10-23 | 현재 완성도: 70

## 1. 가치 정의

김서연은 자기 사이트의 Owner로 계정을 만들고, 동료 작가 이도현에게 초대 링크를 직접 전달해 Author로 합류시킨다. 이도현은 그 링크로 비밀번호를 정해 로그인하고 자기 글을 쓴다. 그 결과 두 사람은 메일 서비스 없이도 같은 사이트에서 각자의 권한으로 일한다.

## 2. 배경

Cloudcore는 공개 가입이 없는 self-hosted 도구다. 아무나 가입할 수 있으면 스팸 계정이 사이트에 글을 쓸 수 있으므로, Owner가 만든 계정과 Owner가 발급한 초대만 허용한다. 메일 발송 기능은 범위 밖이므로 초대와 비밀번호 재설정은 링크를 복사해 직접 전달한다.

## 3. 맥락

인증은 Better Auth를 쓰고 세션 쿠키는 Admin과 같은 origin에서 동작한다. 비밀번호 해시는 무료 플랜 CPU 10ms 안에 들어가야 해서 PBKDF2로 바꿔 끼웠다(ADR-0005). Owner는 단 한 명이고, Author는 Owner가 초대한다. 역할은 `owner`와 `author` 두 가지다.

## 4. 페르소나

김서연은 Owner이며, 새로 합류하는 작가에게 링크를 카카오톡이나 메일로 직접 보낸다. 이도현은 초대 링크를 받고 처음 Cloudcore에 들어온다.

## 5. 메인 시나리오

김서연은 Cloudcore를 처음 열고 Owner 설정 화면에서 이름, 이메일, 비밀번호를 입력해 Owner 계정을 만든다. 그 뒤 로그인 화면에서 그 계정으로 로그인한다.

몇 주 뒤 김서연은 Members 화면에서 이도현의 이메일을 입력해 초대를 만든다. 화면에 초대 링크가 나타나고, 그녀는 링크를 복사해 카카오톡으로 보낸다. 이도현은 링크를 열어 이름과 비밀번호를 정하고 가입한다. 그는 Author로 로그인되어 Posts 목록에서 자기 글만 본다.

이도현이 비밀번호를 잊으면 김서연에게 알린다. 김서연은 Members 화면에서 그를 위해 재설정 링크를 만들고 직접 전달한다. 이도현은 링크에서 새 비밀번호를 정하고 다시 로그인한다.

## 6. 사용자 여정 (one-way)

Owner 설정 → 로그인 → Members에서 초대 생성 → 링크 전달 → Author 가입 → 로그인 → (필요 시) 재설정 링크 발급 → 새 비밀번호

## 7. 유즈 케이스

### UC-A01 사이트에 Owner를 한 번만 만들 수 있다
- 시작 조건: 사이트에 사용자가 한 명도 없다.
- 사용자 행위: 김서연은 이름, 이메일, 비밀번호를 입력해 Owner 계정을 만들 수 있다.
- 결과/정책: Owner가 만들어지면 설정 화면은 닫히고 로그인 화면으로 간다. 이미 사용자가 있으면 설정 요청은 거부된다.
- 관련 시나리오 구간: Owner 설정.

### UC-A02 이메일과 비밀번호로 로그인할 수 있다
- 시작 조건: 김서연에게 계정이 있다.
- 사용자 행위: 김서연은 이메일과 비밀번호로 로그인할 수 있다.
- 결과/정책: 로그인하면 세션 쿠키가 생기고 Admin의 보호된 화면으로 간다. 틀리면 같은 메시지로 실패를 알린다. 짧은 시간에 너무 많이 시도하면 잠시 막힌다.
- 관련 시나리오 구간: 로그인.

### UC-A03 로그아웃할 수 있다
- 시작 조건: 김서연이 로그인했다.
- 사용자 행위: 김서연은 로그아웃할 수 있다.
- 결과/정책: 세션이 사라지고 Admin은 로그인 화면으로 보낸다.
- 관련 시나리오 구간: 로그인 이후.

### UC-A04 Owner는 Author를 초대할 수 있다
- 시작 조건: 김서연이 Owner로 로그인했다.
- 사용자 행위: 김서연은 Members 화면에서 이메일을 입력해 초대 링크를 만들 수 있다.
- 결과/정책: 링크는 한 번만 쓸 수 있고 만료 시각이 있다. `[확인 필요]` 만료 기간. 이미 가입한 이메일은 초대할 수 없다.
- 관련 시나리오 구간: 초대 생성.

### UC-A05 초대받은 사람은 Author로 가입할 수 있다
- 시작 조건: 이도현이 유효한 초대 링크를 열었다.
- 사용자 행위: 이도현은 이름과 비밀번호를 정해 가입할 수 있다.
- 결과/정책: 계정 역할은 `author`이고, 초대는 사용 처리된다. 만료되었거나 이미 쓴 링크는 가입 화면을 열지 않는다.
- 관련 시나리오 구간: Author 가입.

### UC-A06 초대 목록을 보고 취소할 수 있다
- 시작 조건: 김서연이 Members 화면을 열었다.
- 사용자 행위: 김서연은 대기 중인 초대와 만료 시각을 보고, 아직 쓰지 않은 초대를 취소할 수 있다.
- 결과/정책: 취소한 링크는 더 이상 가입에 쓸 수 없다.
- 관련 시나리오 구간: 초대 관리.

### UC-A07 Owner는 재설정 링크를 발급할 수 있다
- 시작 조건: 김서연이 Members 화면에서 이도현을 골랐다.
- 사용자 행위: 김서연은 그를 위한 비밀번호 재설정 링크를 만들어 복사할 수 있다.
- 결과/정책: 메일은 보내지 않는다. 링크는 한 번만 쓸 수 있고 만료 시각이 있다. `[확인 필요]` 만료 기간.
- 관련 시나리오 구간: 재설정 링크 발급.

### UC-A08 재설정 링크로 비밀번호를 바꿀 수 있다
- 시작 조건: 이도현이 유효한 재설정 링크를 열었다.
- 사용자 행위: 이도현은 새 비밀번호를 정할 수 있다.
- 결과/정책: 바뀐 비밀번호로 로그인할 수 있고, 기존 세션은 모두 끝난다. `[가정]`
- 관련 시나리오 구간: 새 비밀번호.

### UC-A09 passkey를 등록해 로그인할 수 있다
- 시작 조건: 김서연이 로그인한 상태다.
- 사용자 행위: 김서연은 계정 화면에서 passkey를 등록하고, 다음 로그인부터 passkey로 로그인할 수 있다.
- 결과/정책: passkey 등록은 최근에 인증한 세션에서만 허용한다. `[확인 필요]` passkey를 1차 범위에 넣을지.
- 관련 시나리오 구간: 로그인.

## 10. 열린 질문과 결정 기록

- `[확인 필요]` passkey를 이번 릴리스에 넣을지, 다음으로 미룰지.
- `[확인 필요]` 초대와 재설정 링크의 만료 기간.
- `[확인 필요]` Author 계정 비활성화(글은 남기고 로그인만 막기)가 필요한지.
- 결정: 공개 가입 없음, 초대 링크는 Owner가 직접 전달(map).
- 결정: 메일 발송 없음(map).
- 결정: 역할은 owner/author 두 가지(map).
- 결정: 비밀번호는 PBKDF2, 배포 후 CPU로 강도 조정(ADR-0005, 티켓 23).
