# 에디터 PRD: 가져오기와 다듬기

버전: v0.2 | 작성자(PM): | 최종 수정일: 2026-10-23 | 현재 완성도: 60 (에디터 라이브러리 미정)

## 1. 가치 정의

필진은 자기에게 익숙한 도구에서 이미 쓴 서평을 우리 CMS로 가져와, 몇 군데만 고쳐 발행한다. 그 결과 필진은 새 편집기를 배우지 않고도 자기 글을 웹진에 올리고, 운영자는 글의 모양이 사이트 스타일에서 벗어나지 않게 유지한다.

## 2. 배경

이 CMS는 글을 쓰는 도구가 아니라 이미 쓴 글을 모아 게시하는 도구다. 필진은 워드, Notion, Google Docs, Markdown에서 글을 쓴다. 그들이 배워야 할 것은 붙여넣기와 발행뿐이어야 한다.

기존 CMS는 빈 편집기를 주고 처음부터 다시 쓰게 하거나, 붙여넣은 서식을 그대로 받아 글마다 글꼴과 색이 달라진다. 우리는 반대다. 최대한 받아오되, 우리가 아는 요소만 남기고 나머지는 버린 뒤 사이트 스타일로 다시 그린다. 그래서 이 화면의 성패는 "붙여넣은 글이 얼마나 온전히 넘어오는가"에 달려 있다.

## 3. 맥락

- Body의 원본은 에디터 JSON이고, 저장할 때 HTML과 plaintext를 함께 만든다(ADR-0002).
- 자동 저장은 브라우저 저장소(IndexedDB)에만 쓰고 서버로 보내지 않는다. 서버에 글이 올라가는 것은 저장 버튼이나 발행을 눌렀을 때뿐이다. 그래서 쓰던 초안은 그 브라우저에만 있고 다른 기기에서는 보이지 않는다.
- 붙여넣은 이미지는 그 초안에 함께 담긴다. 저장하거나 발행할 때 우리 저장소로 업로드되고, 그 전까지는 서버에 없다.
- Body는 표와 각주를 지원한다.
- HTML 생성은 Worker 요청 안에서 일어나므로 무료 플랜 CPU 10ms를 넘지 않아야 한다(ADR-0005).
- 에디터 라이브러리는 아직 정해지지 않았다(티켓 08). 표와 각주 지원은 라이브러리 선택의 조건이 된다.
- 필진은 스스로 발행하고, 운영자의 검토 단계는 없다.

## 4. 페르소나

필진은 코딩을 모르고 GitHub를 쓰지 않는다. 워드나 Notion, Google Docs에서 글을 쓰고, 매달 서평 한 편을 올린다. 표는 책 목록이나 문장 비교에, 각주는 출처와 부연에 쓴다. `[가정]` 오타는 발행 뒤에도 직접 고친다.

운영자(나)는 발행된 글의 오타와 서식을 고치고, 사이트의 모양을 만든다. 붙여넣기가 이상하게 되면 필진이 아니라 내가 먼저 알아차린다.

## 5. 메인 시나리오

필진은 이번 달 서평을 Google Docs에서 쓴다. Admin에서 새 글을 열어 제목을 입력하고, 본문 칸에 글을 붙여넣는다. 제목, 굵게, 목록, 인용, 표, 각주, 이미지가 옮겨진다. 문서의 H1은 글 제목과 겹치지 않도록 H2가 된다. 글꼴, 글자 색, 정렬, 들여쓰기는 사라지고 "일부 서식을 정리했습니다"라는 안내가 뜬다. 이미지는 화면에 보이지만 아직 우리 저장소에 없고, 발행 전까지 대기 상태로 표시된다.

필진은 오타를 고치고, 이미지에 캡션을 달고, 표의 열 하나를 지운다. 각주 번호는 본문에 그대로 있고, 글 끝에 각주 설명이 모여 있다. 입력을 멈추면 초안이 이 브라우저에 저장된다. 필진은 저장을 눌러 서버에 올리고, 발행을 누르면 저장과 함께 대기하던 이미지가 업로드되고 본문 주소가 우리 도메인으로 바뀐 뒤 글이 공개된다. 업로드가 실패하면 발행은 멈추고, 실패한 이미지를 표시하며 다시 시도할 수 있다.

나중에 운영자가 같은 글을 열어 오타를 고친다. 저장하면 Revision이 남고, 다음 Site Build 뒤에 사이트에 반영된다([27](.scratch/cms-rewrite/issues/27-implementation-revisions.md)).

## 6. 사용자 여정 (one-way)

새 글 → 제목 입력 → 본문 붙여넣기 → 정규화 안내 확인 → 이미지 대기 상태 확인 → 오타·캡션·표·각주 다듬기 → 발행 → 이미지 업로드 → 공개

## 7. 유즈 케이스

### UC-E01 다른 도구에서 쓴 글을 붙여넣어 가져올 수 있다
- 시작 조건: 필진이 새 글 또는 편집 화면의 Body에 커서를 두었다.
- 사용자 행위: 필진은 워드, Notion, Google Docs, Markdown에서 복사한 글을 붙여넣을 수 있다.
- 결과/정책: 다음 요소가 살아남는다 — 문단, 제목(문서의 H1은 H2로), 굵게, 기울임, 링크, 목록, 인용, 코드, 구분선, 표, 각주, 이미지. 글꼴, 글자 색, 크기, 정렬, 들여쓰기, 페이지 나눔, 취소선은 버린다. Markdown 원문을 붙여넣으면 같은 요소로 변환한다. 서식이 정리되면 그 사실을 한 번 알린다.
- 관련 시나리오 구간: 붙여넣기.

### UC-E02 가져온 글을 다듬을 수 있다
- 시작 조건: 필진이 Body에 글을 가져왔다.
- 사용자 행위: 필진은 굵게, 기울임, 링크, 인용, 목록, 제목 수준을 툴바나 단축키로 바꿀 수 있다.
- 결과/정책: 화면에 보이는 모습이 저장되는 모습과 같다. 붙여넣기 뒤에 남은 불필요한 빈 문단은 지울 수 있다.
- 관련 시나리오 구간: 다듬기.

### UC-E03 이미지는 저장하거나 발행할 때 업로드된다
- 시작 조건: 필진이 이미지를 붙여넣었거나 이미지 Card에 파일을 넣었다.
- 사용자 행위: 필진은 이미지를 본문에서 보고, 캡션과 대체 텍스트를 적고, 저장하거나 발행할 수 있다.
- 결과/정책: 편집하는 동안 이미지는 브라우저 안에만 있고 "업로드 전"으로 표시된다. 자동 저장은 그 이미지를 브라우저 초안에 함께 담을 뿐 업로드하지 않는다. 저장이나 발행을 누르면 업로드가 끝난 뒤 본문의 이미지 주소가 우리 도메인으로 바뀐다. 업로드가 하나라도 실패하면 저장·발행은 완료되지 않고, 실패한 이미지를 표시하며 다시 시도할 수 있다.
- 관련 시나리오 구간: 발행 → 이미지 업로드.

### UC-E04 표를 넣고 다듬을 수 있다
- 시작 조건: 필진이 표를 붙여넣었거나 `/` 메뉴에서 표를 골랐다.
- 사용자 행위: 필진은 표의 행과 열을 추가·삭제하고, 머리글 행을 지정하고, 칸 안에 글을 쓸 수 있다.
- 결과/정책: 표는 Body의 일부이고 Card가 아니다. Site에서는 화면보다 넓은 표를 가로로 스크롤해 읽을 수 있다.
- 관련 시나리오 구간: 다듬기.

### UC-E05 각주를 넣을 수 있다
- 시작 조건: 필진이 각주가 있는 글을 붙여넣었거나 각주를 새로 넣으려 한다.
- 사용자 행위: 필진은 본문에 각주 참조를 넣고, 글 끝의 각주 설명을 쓰거나 고칠 수 있다.
- 결과/정책: 번호는 본문 순서대로 자동으로 매겨지고, 글 끝에 설명이 모인다. Site에서는 번호를 누르면 설명으로 이동하고 다시 본문으로 돌아올 수 있다. plaintext에도 각주 설명이 들어간다.
- 관련 시나리오 구간: 다듬기.

### UC-E06 Card를 넣을 수 있다
- 시작 조건: 필진이 Body에서 새 줄에 있다.
- 사용자 행위: 필진은 `/` 메뉴나 툴바로 이미지, 코드, 임베드, 콜아웃, 구분선, HTML, CTA 버튼을 넣고 옵션을 정할 수 있다.
- 결과/정책: 코드는 언어를 고를 수 있고, HTML은 허용 태그만 남긴다. 임베드는 허용 제공자만 iframe으로 출력하고, 그 밖의 URL은 링크로만 남긴다. CTA 링크가 비면 버튼을 출력하지 않는다. `[가정]`
- 관련 시나리오 구간: 다듬기.

### UC-E07 초안이 브라우저에 자동으로 남는다
- 시작 조건: 필진이 Body나 메타데이터를 고쳤다.
- 사용자 행위: 필진은 입력을 멈추면 "이 브라우저에 저장됨"을 볼 수 있고, 새로고침하거나 브라우저를 닫았다 다시 열어도 쓰던 내용을 이어서 볼 수 있다.
- 결과/정책: 자동 저장은 브라우저 저장소에만 쓰고 서버로 보내지 않는다. Revision도 만들지 않는다. 서버 저장은 저장 버튼이나 발행으로만 일어나며, 그때 화면은 "서버에 저장됨"으로 바뀐다. 브라우저 저장에 실패하면(용량 초과 등) 그 사실을 알리고 저장 버튼을 안내한다. 자동 저장은 60초마다 일어난다. `[확인 필요]` 초안 보관 기간.
- 관련 시나리오 구간: 다듬기.

### UC-E08 서버에 저장하지 않은 변경이 있으면 이탈을 확인한다
- 시작 조건: 필진이 서버에 저장하지 않은 변경을 가진 채 화면을 떠나려 한다.
- 사용자 행위: 필진은 경고를 보고 남거나 떠날 수 있다.
- 결과/정책: 떠나도 초안은 이 브라우저에 남아 있다고 알린다. 다른 기기나 다른 브라우저에서는 보이지 않는다는 것도 함께 알린다. 발행 전 이미지는 아직 서버에 없다는 것도 알린다. 브라우저 새로고침·닫기에서는 브라우저 기본 경고를 쓰고, Admin 안 이동에서는 확인 다이얼로그를 쓴다.
- 관련 시나리오 구간: 편집 종료.

## 10. 열린 질문과 결정 기록
