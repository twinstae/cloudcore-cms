# Site와 발행 PRD

버전: v0.1 | 작성자(PM): | 최종 수정일: 2026-10-23 | 현재 완성도: 70

## 1. 가치 정의

김서연은 사이트 이름·설명·로고·메뉴를 한 화면에서 정하고, 글을 발행하면 독자가 자기 도메인의 빠른 정적 페이지에서 그 글을 읽는다. 그 결과 김서연은 테마 코드를 만지지 않고도 자기 사이트의 모습과 발행 흐름을 관리한다.

## 2. 배경

Site는 요청마다 서버에서 그리지 않고, 발행된 Content로 정적 페이지를 미리 만들어 Workers Static Assets로 서빙한다(ADR-0004). 방문자 트래픽이 Worker 요청·CPU 한도를 쓰지 않고, 캐시 설계도 필요 없다. 대신 발행이 반영되기까지 빌드 시간이 걸린다.

## 3. 맥락

Site는 Astro 정적 빌드이고, 빌드할 때 인터넷에 공개된 읽기 API에서 발행된 글만 가져간다. 발행·수정·발행 취소·예약 발행 시각이 되면 API가 Workers Builds Deploy Hook을 호출해 재빌드를 요청한다. 계정 전체 동시 빌드는 1개이고 빌드 상한은 20분이다. 도메인은 `example.com`(Site), `admin.example.com`(API+Admin), `media.example.com`(R2) 세 개로 나눈다.

## 4. 페르소나

김서연은 사이트 제목과 소개 문구, 상단 메뉴, 소셜 링크를 직접 정한다. 독자는 검색이나 링크로 들어와 글을 읽고, 김서연의 다른 글과 태그를 따라간다.

## 5. 메인 시나리오

김서연은 Admin의 Site Settings에서 사이트 제목을 "서연의 기술 노트"로, 설명을 한 줄 소개로 적고 로고 이미지를 올린다. 상단 메뉴에 Home, About, Tags를 넣고, About은 Page로 만든 글을 연결한다. timezone을 Asia/Seoul로 정한다.

그녀가 글을 발행하면 API가 발행 상태를 바꾸고 Site Build를 요청한다. 몇 분 뒤 빌드가 끝나고, 독자가 `example.com`을 열면 새 글이 첫 화면에 보인다. 독자는 글을 눌러 본문을 읽고, 글 아래의 태그를 눌러 같은 태그의 글 목록으로 간다.

김서연이 사이트 제목을 바꾸면 다음 빌드부터 모든 페이지에 새 제목이 적용된다. 빌드가 실패하면 Admin의 Site Settings 화면에 마지막 빌드가 실패했다는 표시가 남고, 독자는 이전에 성공한 빌드를 계속 본다.

## 6. 사용자 여정 (one-way)

Site Settings 입력 → 저장 → (발행) → Site Build 요청 → 빌드 완료 → 독자가 Site에서 읽음 → 태그·목록으로 이동

## 7. 유즈 케이스

### UC-S01 사이트 기본 정보를 정할 수 있다
- 시작 조건: 김서연이 Owner로 로그인했다.
- 사용자 행위: 김서연은 사이트 제목, 설명, 로고, 아이콘, 대표 OG 이미지, 대표 색상, timezone을 정하고 저장할 수 있다.
- 결과/정책: 저장하면 공개 읽기 API가 새 값을 돌려주고, 다음 Site Build부터 모든 페이지에 적용된다.
- 관련 시나리오 구간: Site Settings 입력.

### UC-S02 내비게이션 메뉴를 정할 수 있다
- 시작 조건: 김서연이 Site Settings를 열었다.
- 사용자 행위: 김서연은 메뉴 항목의 이름과 연결할 Page 또는 외부 URL을 정하고 순서를 바꿀 수 있다.
- 결과/정책: Site의 상단과 푸터는 이 목록을 그대로 쓴다. 연결한 Page가 발행 취소되면 그 항목은 Site에서 빠진다. `[가정]`
- 관련 시나리오 구간: 메뉴 정하기.

### UC-S03 소셜 링크를 정할 수 있다
- 시작 조건: 김서연이 Site Settings를 열었다.
- 사용자 행위: 김서연은 소셜 링크의 이름과 URL을 추가하고 지울 수 있다.
- 결과/정책: Site는 링크를 아이콘과 이름으로 보여 준다. `[가정]` 아이콘은 이름으로 추정한다.
- 관련 시나리오 구간: 소셜 링크.

### UC-S04 독자는 발행된 글을 읽을 수 있다
- 시작 조건: 글이 `published`이고 마지막 Site Build가 끝났다.
- 사용자 행위: 독자는 첫 화면, 글 페이지, Page, 태그 페이지에서 발행된 글을 읽을 수 있다.
- 결과/정책: 초안과 예약 글은 어떤 공개 페이지에도 나오지 않는다.
- 관련 시나리오 구간: 독자가 글을 읽는다.

### UC-S05 첫 화면에서 최근 글과 페이지 이동을 볼 수 있다
- 시작 조건: 독자가 Site 첫 화면을 열었다.
- 사용자 행위: 독자는 최근 글 목록을 보고 다음 페이지로 넘길 수 있다.
- 결과/정책: 한 페이지에 정해진 개수만 보여 주고 `/page/2/` 형태로 넘긴다. `[확인 필요]` 페이지당 글 수.
- 관련 시나리오 구간: 독자가 첫 화면을 연다.

### UC-S06 태그 페이지에서 같은 태그의 글을 볼 수 있다
- 시작 조건: 독자가 글에서 태그를 눌렀다.
- 사용자 행위: 독자는 `/tag/<slug>/`에서 그 태그가 붙은 발행 글 목록을 볼 수 있다.
- 결과/정책: 태그가 붙은 글이 없으면 목록은 비어 있고 태그 이름만 보인다. `[가정]`
- 관련 시나리오 구간: 태그 페이지.

### UC-S07 RSS와 sitemap을 제공한다
- 시작 조건: Site Build가 끝났다.
- 사용자 행위: 독자나 검색 엔진은 `/rss/`와 `/sitemap.xml`을 요청할 수 있다.
- 결과/정책: RSS에는 발행 글의 제목·링크·요약·발행 시각이, sitemap에는 발행 글·Page·태그 URL이 들어간다.
- 관련 시나리오 구간: 독자가 구독한다.

### UC-S08 발행하면 Site Build가 요청된다
- 시작 조건: Content가 발행·수정·발행 취소되었거나 예약 시각이 되었다.
- 사용자 행위: 김서연은 발행 후 몇 분 안에 Site에서 결과를 확인할 수 있다.
- 결과/정책: API는 Deploy Hook을 한 번 호출하고, 빌드가 이미 진행 중이면 플랫폼이 합쳐 처리한다. 같은 사건이 짧은 시간에 여러 번 생겨도 빌드 요청을 남발하지 않는다. `[확인 필요]` debounce 여부.
- 관련 시나리오 구간: 발행 → 빌드.

### UC-S09 빌드 상태를 확인할 수 있다
- 시작 조건: 김서연이 Site Settings를 열었다.
- 사용자 행위: 김서연은 마지막 빌드의 시각과 성공·실패를 볼 수 있다.
- 결과/정책: 실패하면 다시 빌드를 요청하는 버튼을 쓸 수 있다. `[가정]`
- 관련 시나리오 구간: 빌드 실패.

### UC-S10 다크 모드를 지원한다
- 시작 조건: 독자가 Site를 연다.
- 사용자 행위: 독자는 시스템 설정에 따라 dark 테마로 읽을 수 있고, 화면의 토글로 직접 바꿀 수 있다.
- 결과/정책: 첫 페인트 전에 인라인 스크립트로 테마를 정해 깜빡임을 막는다.
- 관련 시나리오 구간: 독자가 글을 읽는다.

## 10. 열린 질문과 결정 기록

- `[확인 필요]` 초안 미리보기 링크(서명 URL)를 1차 범위에 넣을지.
- `[확인 필요]` 첫 화면 페이지당 글 수와 페이지네이션 형태.
- `[확인 필요]` 빌드 요청 debounce와 실패 시 재시도 횟수.
- 결정: Site는 정적 빌드, 발행 시 재빌드, 빌드 시 공개 읽기 API 호출(ADR-0004).
- 결정: 발행은 Deploy Hook POST, 플랫폼이 빌드를 합침(티켓 17).
- 결정: 도메인 3개 구성과 media 커스텀 도메인(ADR-0003).
- 결정: 사이트 URL 규칙은 Ghost와 같다(map): `/{slug}/`, `/tag/{slug}/`, `/page/N/`, `/rss/`, `/sitemap.xml`.
