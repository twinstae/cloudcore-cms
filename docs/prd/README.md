# Cloudcore PRD

버전: v0.2 | 최종 수정일: 2026-10-23 | 현재 완성도: 70

기능별 PRD의 공통 전제다. 결정 근거는 `docs/adr/`, 용어는 `GLOSSARY.md`, 확정된 제품 정책은 `.scratch/cms-rewrite/map.md`를 따른다. 여기 없는 정책은 각 PRD에서 `[확인 필요]`로 표시한다.

## 가치 정의

웹에 자기 글을 공유하려는 운영자는 Ghost 같은 유료 서비스나 서버 관리 없이 자기 도메인에서 글을 공개하고 싶지만, 필진에게 글을 맡기려면 필진도 도구를 배워야 하고 화면을 직접 고치기도 어렵다. 운영자는 Cloudflare 위에서 도는 Cloudcore를 자기 계정에 올려 정적 Site와 동적인 Admin을 함께 얻고, 필진은 자기 도구에서 쓴 글을 붙여넣어 발행하며, 독자는 링크로 읽고 공유해, 운영자가 적은 비용으로 콘텐츠와 화면을 자기 계정 안에서 관리한다.

## 페르소나

아래는 지어낸 인물이 아니라, 이 도구를 실제로 쓸 사람들의 조건이다. 확인되지 않은 것은 `[확인 필요]`로 둔다. 나이·주거·차량처럼 제품의 결정을 바꾸지 않는 항목은 적지 않는다.

### Owner: 나

나는 개발자다. 물리학과를 나와 프로그래머로 일하고, 법을 공부하고, 여러 스터디 모임과 단체 활동을 한다. 코드를 읽고 고칠 수 있어 Cloudcore를 내 Cloudflare 계정에 직접 올리고, 문제가 생기면 로그와 코드를 열어 본다. 최근에는 디자인을 공부하고 있고 UI를 직접 깎는 것을 좋아한다. 이 사이트의 화면은 내가 만든다.

우리 책 모임은 매달 각자 서평을 쓰기로 했고, 그 글을 웹진처럼 모아 공유하기로 했다. 내가 하는 일은 이미 쓴 글을 모아 사이트에 올리고, 필진을 초대하고, 링크로 공유하는 것이다. 딱딱한 B2B 화면이 아니라 사람 냄새 나고 아기자기한 사이트를 만들고 싶다.

내가 원하는 것은 세 가지다. 내가 직접 고칠 수 있는 화면, 필진이 로그인해서 자기 글만 올릴 수 있는 권한, 독자가 링크로 읽고 공유할 수 있는 공개 사이트. 필진은 스스로 발행하고, 나는 발행된 글을 나중에 고칠 수 있다.

### 필진: 초대받은 사람들

한 사람이 아니라 여럿이고, 서로 다른 삶을 산다. 대학원생, 청소년, 직장인, 예술가, 단체 상근자. 나이도 사는 곳도 다르고, 아이가 있는지 차가 있는지는 이들에게 공통점이 아니다.

공통점은 두 가지다. 대부분 코딩을 할 줄 모르고 GitHub 같은 것을 쓰지 않는다. 그리고 글과 책을 좋아하거나, 적어도 읽고 써 보려고 노력한다.

이들은 자기에게 익숙한 도구에서 글을 쓴다. 워드, Notion, Google Docs, Markdown. 쓴 글을 우리 CMS로 복사해 붙여넣는다. 이들이 배워야 하는 것은 로그인과 "내 글 올리기"뿐이다. 메뉴가 많거나 설정이 복잡하면 안 된다.

매달 서평 한 편이 숙제다. 자기 글은 자기가 올리고, 발행도 자기가 한다. 검토나 승인을 기다리지 않는다. 오타나 잘못 쓴 부분은 발행 뒤에도 직접 고친다.

붙여넣은 글은 우리 에디터가 아는 요소만 남기고, 그 밖의 서식은 버린 뒤 사이트 스타일로 다시 그린다. 필진은 옮겨진 글에서 자잘한 수정만 한다. 붙여넣은 이미지는 화면에 먼저 보이고, 저장하거나 발행할 때 우리 저장소로 업로드된다. 각주와 표도 옮겨진다.

### 독자: 모임 사람들과 링크로 들어온 사람

책 모임 회원이 먼저 읽고, 그중 일부가 SNS나 메신저로 링크를 공유한다. 링크를 받은 사람은 우리를 모를 수 있으므로 공유 카드에 글 제목과 쓴 사람이 보여야 한다. 독자는 로그인하지 않는다.

## 읽는 법

각 PRD는 가치 정의, 배경, 페르소나(기능에 필요한 부분만), 메인 시나리오, 사용자 여정, 유즈 케이스(UC), 예외 케이스, QC 체크리스트, 열린 질문 순서다. 티켓은 유즈 케이스 ID를 인용하고, 완료 조건은 QC 항목에서 가져온다.

01·03·04·05·06의 본문은 아직 이전에 지어낸 인물(김서연·이도현)을 인용하고 있다. 각 문서를 리뷰할 때 이 페르소나에 맞춰 고친다.
